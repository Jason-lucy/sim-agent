# Non-goals — 明确不做什么

> 个人项目的死法只有一种：范围蔓延。
> 本文件是纪律工具。任何新想法先对照这里，命中即砍。修改本文件需要冷静期（24 小时）。

| # | 永不做（本项目范围内） | 理由 |
|---|---|---|
| 1 | **自研仿真内核** | SimPy 已成熟开源（MIT）；自研是纯工作量黑洞，且不体现 Agent 能力 |
| 2 | **GUI 拖拽建模器** | 前端工作量巨大；聊天界面 + 表单 + 图表已覆盖作品集需求 |
| 3 | **多行业通用建模** | schema 一旦通用就不可控，LLM 生成正确率会崩；锁死排队/生产场景族 |
| 4 | **商业级性能 / 大规模仿真** | 与转行目标无关 |
| 5 | **用户账号 / 多租户 / 付费** | 这是作品集，不是产品；商业化验证后再谈 |
| 6 | **与 Simul8 文件兼容/导入导出** | ⚠️ 在职合规红线：不用公司资产、不涉密、不导入公司格式 |
| 7 | **「国产替代」叙事** | 业余 MVP 撑不起这个定位，写进定位会显得不专业 |
| 8 | **手机端 / 离线版 / 私有化部署** | 全部推迟；一个能点开的网页链接已足够 |
| 9 | **自训练/微调 LLM** | 用 API + 提示工程 + 结构化输出解决；微调是另一个项目 |
| 10 | **3D 动画 / 可视化画布** | Plotly 统计图表已足够；3D 是重资产赛道，个人不做 |
| 11 | **制造业产线场景（当前版本）** | 定位聚焦服务业（D-006）：制造业对数据精度要求高（节拍/MTBF/换型），粗数据撑不起可信度；中国商用/服务业 DES 是真空白缝隙 |

## 场景族边界（In-scope 红线）

只支持**模型抽象收敛**的排队/服务流程场景（D-006）：到达过程、服务过程、资源数、队列规则、（扩展）优先级、放弃流失、波峰时段、多阶段服务链。典型场景：客服中心、银行网点、医院门诊、餐饮翻台、门店收银、政务大厅。
**制造业产线、物流分拣等场景超出当前范围** → 明确报「暂不支持」而不是硬生成。
